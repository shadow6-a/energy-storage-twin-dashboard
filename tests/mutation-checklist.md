# 变异测试清单（门禁断言可信度背书）

> 目的：证明断言「能抓错」而不是「永远绿」。断言越加越多，若不验证抓错能力，门禁会退化成"绿就行"。
> 用法：**v1.0 发布前抽 3–5 条跑一遍**（改坏 → 跑 `tests/regression.ps1` → 确认期望断言红 + exit 1 → 恢复）。
> 新增断言时同步在本清单登记对应变异项。

|---|---|---|---|

## 维护规则

- 每新增一类断言，在本清单补一行「破坏什么 → 期望哪条红」
- 抽测不必全跑；但**发布里程碑前至少抽 3 条，且必须包含最近新增的断言**
- 变异时在改动处留 `/* MUTATION-TEST */` 注释，跑完立即恢复，恢复后必须重跑门禁确认全绿
