储能集群运维数字孪生可视化前端原型

面向储能电站与新能源集成商，可作为方案原型与 UI 验收基准， 支持对接 BMS / EMS 数据源，落地为控制室调度大屏。 本页从运维业务视角说明这套方案解决什么问题、与通用大屏的差异、以及落地边界—— 落地细节见 feasibility.md，演示顺序见 demo-script.md。

TL;DR

三个核心价值（60 秒版）

FOR DECISION-MAKERS
01 · 面向长期值守的视觉设计

针对 7×24 小时控制室值守场景：低饱和深色底 + 高对比关键数值，降低视觉干扰与值守人员视觉疲劳；告警信息四级色唯一且全局贯穿，永远优先突出；动效仅保留告警脉冲与功率链路，符合电力运维人员的读屏习惯，而非参观展示的炫技。

02 · 告警闭环 = 完整运维流转

未确认 → 确认 → 闭环 / 抑制，是完整的运维工单流转逻辑，不是简单提示弹窗；告警数据单向同步，保证台账、地图、舱体视图数据一致性，运维人员无需多界面核对信息——从一条告警定位到故障电池簇只需 4 次点击。

03 · 解耦设计，对接真实设备

模拟数据层与视图层分离，接口边界清晰（字段映射表已给出），可平滑对接现场 BMS / PCS / EMS 真实数据源；自研轻量 3D 性能可控，工控机核显即可运行——这是可演进的工程方案，不是只能看的原型。

03

业务约束如何转化为设计响应

CONSTRAINTS → DESIGN

强光控制室 → 面板底色压深、关键数值高对比等宽字体（1.5m 距离可辨读；禁用大面积渐变避免环境反光——直接目标是降低值守人员 8 小时以上的视觉疲劳。

告警优先 → 四级告警色全局唯一且贯穿 2D/3D（信标脉冲、台账色条、舱体颜色、图表阈值共用一套语义），值班员不需要学习第二套颜色语言：异常信息永远最先被看到。

调度策略联动 → 策略不是贴在底部的开关：切换后计划曲线重算、链路流向速度变化、底部窗口同步——调度员获得的是直观推演能力，而非一个按钮。

下钻闭环 → 空间（L0→L3）与数据（集群→站→舱→簇）同步收敛，最终落到电池簇的可执行信息（压差、绝缘、循环），支撑"看到问题→定位问题→处置问题"的完整动作链，缩短故障定位时间。

06

两条落地路线

ROUTE A / ROUTE B
路线 A · 轻量落地（成本低，优先推荐）

适用于已有 EMS 后台的集成商：只需一套前端可视化页面。我方提供整套 UI + 交互源码 + 组件规范，贵方后端对接 MQTT / WebSocket 数据源。

交互逻辑、告警业务逻辑、UI 规范 100% 复用，对接工作量约 13–14 人天（详见 quotation-outline.md）。

路线 B · 完整方案

适用于暂无成熟 EMS 的情况：联合配套后端开发，补齐权限分级、历史存储、告警推送、审计日志，替换高精度 3D 模型，形成完整调度工作站。

对应升级路径 ③–⑤（见 feasibility.md 第 8 节），工作量约 40–45 人天。

07

数据对接与技术边界

INTEGRATION

接口已预留：界面层只消费 data.js 的聚合接口（STATIONS / ALERTS / planAt / buildSeries / aggregate）。对接真定 BMS/PCS/EMS 时，仅需替换该层为 WebSocket 推送或 REST 轮询，2.5s 数据帧与全部渲染逻辑无需改动。

字段映射表：站级 SOC/温度/功率、告警等级/状态、计划/实际曲线、簇级压差/电流等核心字段与设备侧来源的对应关系，已在 feasibility.md 第 2 节 给出。

3D 方案边界：自研 Canvas 轻量引擎适合点位/舱体/簇级抽象表达（正是调度场景所需），不承接设备级 CAD 精度模型；场景描述层与引擎解耦，可平滑升级 Three.js 并保留场景结构。

性能基线：≤30 站流畅、60fps、无独立显卡要求、全页 JS ≤ 130KB 且断网可查看静态视图/流程图/规范——工控机即可部署（配置要求见 feasibility.md 第 3 节）。

架构红利 · 场景与引擎解耦：拓扑 Canvas 与全部图表/SVG 均按容器实际尺寸渲染，页面采用流式网格布局（固定 px 字号不随视口缩放压缩）——1024 笔记本到 4K 拼接屏同一套代码零改动适配，字号可读性始终恒定。
